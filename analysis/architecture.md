# Frontend architecture evidence

Scope: downloaded homepage HTML and the 12 JS/CSS files present under `analysis/client` at inspection time. Offsets below are zero-based JavaScript/.NET string character offsets in the UTF-8 decoded file, **not byte offsets**. Files are mostly minified single-line output. No runtime execution is claimed by this static inspection; root investigation supplies REA runtime evidence separately.

## Proven from Client Files

- **Next.js 15.5.9, App Router**: `_next/static/chunks/255-cb395327542b56ef.js` offset 55366 contains `window.next={version:"15.5.9",appDir:!0}`. `index.html` offset 9377 contains the streamed React Flight payload `__next_f.push`, with client-reference records, `parallelRouterKey:"children"`, and a server-produced page tree. `_next/static/chunks/app/page-55766a91d422cd0e.js` and `app/layout-113c514e53b9114b.js` are route and shared-layout client chunks.
- **React 19.2.0-canary-0bdb9206-20250818**: `255-cb395327542b56ef.js` offset 21437 explicitly assigns `t.version="19.2.0-canary-0bdb9206-20250818"`; renderer chunk `4bd1b696-c023c6e3521b1417.js` offset 170478 checks that same version against React. This is the shipped version string, not a guessed stable React version.
- **Webpack**: `app/page-55766a91d422cd0e.js` offset 0 uses `self.webpackChunk_N_E`; numeric modules, `n.e` dynamic chunks, and the separate `webpack-e8ca3fce59cfd3ef.js` runtime are present.
- **Tailwind CSS v4.1.11**: CSS offset 16784 has the exact `/*! tailwindcss v4.1.11 | MIT License | https://tailwindcss.com */` banner. CSS also contains v4 `@layer`, `@property`, CSS variables, and utility selectors.
- **Route navigation**: page chunk module 5974, offsets 156–900, declares `[{label:"about",href:"/"},{label:"projects",href:"/projects"},{label:"writing",href:"/writing"},{label:"cabinet",href:"/cabinet"}]`; `usePathname()` marks `/` exactly and other sections by `startsWith`. Navigation uses module 2619's Next Link wrapper; root can cross-reference that module in chunk 176 if needed. Actual SSR HTML has normal `<a href>` links and `aria-current="page"` on about (HTML offset 4648).
- **Shared canvas selection by pathname**: layout chunk offset 46129: `function G(){let e=(0,o.usePathname)();return e.startsWith("/writing")?null:e.startsWith("/projects")?...J...:e.startsWith("/cabinet")?...R...:...F...}`. Footer module 9304 changes the caption for `/projects`, `/writing/`, `/writing`, `/cabinet`, and default.
- **Layering/layout**: HTML offsets 2740–5600 contain fixed full-viewport `overflow-hidden` scene container, `aria-hidden="true"`, pointer-transparent projected labels, radial dark wash (`fixed inset-0 z-[1]`), and `main` with `relative z-10 flex h-svh flex-col justify-center py-12 text-[14px] leading-[1.7] sm:py-16`. Main text width is `max-w-[26rem]`; header is `shrink-0`, body is `page-scroll min-h-0 shrink overflow-y-auto` (HTML offset 5610). Inner scroll prevents long text from pushing the fixed background.
- **Colors/type**: CSS offset 20040: `--color-bg:#0c0b0a;--color-ink:#e9e2d3;--color-muted:#8f877a;--color-faint:#3a3631;--color-accent:#d98b5f`. Body uses `var(--font-serif)`, mapped at offset 18703 to Libertinus Serif; display/nav uses Libertinus Sans; uppercase labels use Archivo Narrow. Inter and Libertinus Mono are also shipped, but their presence alone does not establish homepage use.
- **Font assets**: local `@font-face` Latin subsets, all `font-display:swap`: Libertinus Sans regular `3f9720238916fc53.p.woff2` (CSS 1549), bold `5b1bdc9b4fac8e1f.p.woff2` (3421); Libertinus Serif italic 400 `c703775db5032cb7.p.woff2` (5675), italic 600 `453e59459e0469c5.p.woff2` (7806), normal 400 `a2ca94e396879f92.p.woff2` (9937), normal 600 `7b8c9648e0bec209.p.woff2` (12068); Libertinus Mono regular `dffea479e72aaa58.p.woff2` (12859); Inter variable 100–900 `e4af272ccee01ff0-s.p.woff2` (14849); Archivo Narrow variable 400–700 `07d0cf9a4e6818b2-s.p.woff2` (16120). Prefix all with `/_next/static/media/`. CSS proves declared assets; this worker did not download or inspect font binary metadata.
- **Responsive CSS**: 40rem/48rem/64rem/80rem breakpoints (CSS offsets 46891, 47793, 48025, ~48900). Homepage text changes from 1rem horizontal padding to zero at 40rem; vertical padding increases from 3rem to 4rem. Bottom-right chart is `hidden sm:block` (HTML ~3600) and thus absent below 40rem.
- **Responsive scene**: layout offset ~16290 sets canvas dimensions from container size, uses camera fitter `(32, aspect, 2)`, changes projection with `A.setViewOffset(...,.12*width,...)` for portrait aspect, and observes container via `ResizeObserver` (16655). Device pixel ratio is capped at 2 (2694). This is explicit camera/layout adaptation, not solely CSS scaling.
- **Input separation**: body CSS `cursor:grab;touch-action:pinch-zoom`; `[data-no-orbit]{cursor:auto}`. Pointerdown rejects `a, button, [data-no-orbit]` (layout 13455), so content/links do not start camera drags. Root dataset `orbiting` turns all cursors to grabbing and disables text selection. Double-click resets camera orientation. These are custom pointer handlers, not sufficient evidence for Three OrbitControls.
- **Text visibility state**: page chunk module 8943 at offset 2395 uses React `useState(false)`. Button sets/removes `document.documentElement.dataset.textHidden`; cleanup deletes it. CSS offset 50084: `.hideable{transition:opacity .5s,visibility .5s}html[data-text-hidden] .hideable{opacity:0;visibility:hidden}`. Button changes `aria-pressed`, `aria-label`, title, eye icon, and moves to fixed upper-left placement when text hidden. No state store library is needed for this feature.
- **Motion/accessibility**: CSS ~50400 defines `.rise` fade/8px translate animation with .9s timing; `@supports(animation-timeline:view())` adds scroll reveals; `prefers-reduced-motion:reduce` makes reveals visible and removes CSS animation. Renderer independently queries reduced motion and uses fixed progress `.485` plus event-driven redraw instead of RAF where appropriate (layout 2600, 16300–17100). Focus outlines use accent color. Tooltip module 8353 adjusts tooltip margins to stay 12px within viewport and supports pointer/focus plus `aria-describedby`.
- **Correction to requested controls**: the four names are hover labels, not toggles. Their DOM consists of pointer-events-none `<span>` elements with opacity 0 and refs; the labels are projected onto screen and revealed by pointer hit tests in rendering code. The `brightness` and `time` text are **chart axes**, not sliders: HTML has a 156×72 `<canvas>` inside `pointer-events-none ... hidden sm:block`, rotated brightness label and time label. No `<input>` exists in the captured HTML or page/layout UI code. The chart is an observational microlensing light curve and receives animation progress. Prototype toggles/sliders can be useful additions but must be labeled a proposed interface, not a recovered original control scheme.

## Inferred

- Likely source organization: `app/layout.tsx` with global background-scene switcher and caption, `app/page.tsx` with mostly server-rendered bio plus small client components (Navigation, Tooltip, HideTextButton); route pages under `app/projects`, `app/writing`, and `app/cabinet`. Chunk paths/Flight tree strongly support App Router structure, but filenames, TypeScript use, and original component names are not recoverable from minified artifacts.
- Font wrappers with generated `__variable_*` and `__className_*`, metric fallback definitions, and local `/_next/static/media/` outputs strongly suggest `next/font` (probably Google font helpers); original font imports/configuration remain unavailable.
- Development used React/Next build pipeline and Tailwind v4. Exact editor, package manager, operating system, Node version, deployment platform, authored JS vs TS, and original source tree are not established.

## Hidden / Obfuscated / Unknown

- Original source/component names, comments outside retained shader strings, package.json/lockfile, exact Three source dependency specification, authored TS types, and source maps are absent from the inspected files. No `sourceMappingURL` marker found in these downloaded JS files; source-map availability on the server was not tested here.
- Server-rendered HTML and Flight payload prove server/compile-time rendering output; they do **not** distinguish static pre-rendering from per-request SSR. Server implementation, build-time content acquisition, and hosting cannot be reconstructed from this homepage capture alone.
- No CMS vendor strings (`supabase`, `contentful`, `sanity.io`, `prismic`, `wordpress`) appeared in bounded search across the 11 downloaded JS files. Homepage content is embedded in HTML/Flight. That does not prove absence of a CMS or APIs on other pages, at build time, or behind server components. Framework generic fetch/server-action code is not evidence the portfolio uses a custom backend.
- This worker did not fetch or inspect the linked projects/writing/cabinet route responses, lazy-loaded route chunks, their CMS network activity, or external links. Shared background branches establish intent but not full route behavior.
